Read this first

How to read this document

These are structural wireframes, not final visuals. Layout, hierarchy, and content are decided here; illustration, photography, and motion are not.

They are drawn with real design-system values — the real type ramp, the real #995a00, real 8/16 spacing, real chip and badge components — because the visual layer is already settled in the rules document. Drawing grey boxes first would mean redrawing everything a week later. Grey blocks marked ILLUSTRATION or PHOTO are the only genuine placeholders.

Content is real, not lorem. Manufacturer names, quantities, and roles are drawn from the PRD's own examples so that layout problems surface here rather than in UAT. The sample user is deliberately the hard case: Ramesh Kumar — Barbender in Steel, Contractor in Cement, Painter in Paints, linked to two Distributors and one Dealer.

On typography

The design system is Lato. Artifact pages cannot load external fonts, so these frames render in the system humanist sans as the closest honest stand-in. Final designs and the built app use Lato — the size, weight, and line-height values shown are already the real ones.

PRD §4.13 · §9 Accessibility

Ten rules the audience imposes

These are requirements, not preferences. Every screen in this document was drawn against them, and any screen that violates one is wrong regardless of how it looks.

01

Numbers before words

A barbender recognises "500 kg" faster than any sentence containing it. Quantity and brand lead every row; prose is secondary and small.

02

Icon and label, never icon alone

Every tab, action, and status carries a text label. Icon-only is permitted only for back, close, and call.

03

48 dp minimum tap target

Primary buttons are 48–56 dp tall. These hands are calloused and often gloved; the design system's 40 dp button gets padded, not shrunk.

04

One decision per screen

No screen asks for two unrelated choices. Filters live in a sheet, not inline. Depth is preferable to density.

05

No nested menus

Maximum two taps from a tab to any Phase 1 destination. Nothing hides behind a hamburger or an overflow menu.

06

Status is colour + icon + word

Colour alone is never the signal. Every chip pairs a hue with a glyph and a label, so it survives colour-blindness, sunlight, and a cheap panel.

07

A human is always one tap away

Call and WhatsApp support appear on every error, every empty state, and every dispute. For a low-trust user, the phone number is the real safety net.

08

Indic-script sizing

Devanagari, Tamil and Telugu run 15–30% longer than Latin and sit taller in the line. No fixed-width buttons, no fixed-height text containers, no truncated status words.

09

Offline is a normal state

Work sites have no signal. Cached data shows with a timestamp; queued actions show as pending. Neither is styled as an error.

10

Never blame the user

An unregistered number is not a failure — it is an instruction to ask their Distributor. Copy assumes the user did nothing wrong, because usually they didn't.

PRD §4.0

Language selection

The first screen of the app, shown once, before login. It has to come first because the login screen itself must already be in a language the user reads — a Hindi-only speaker cannot be asked to navigate an English login in order to reach a language setting.

The list is served by the portal and configured by Ops, not hardcoded. Humbee operates across states with different scripts, so enabling Gujarati or Tamil must be a data change, never an app release. The layout is built to absorb ten or more entries.

Font dependency — raise before build

The HUMBEE design system is Lato, which covers Latin only. Devanagari, Gujarati, Tamil, Telugu, Kannada and Bengali are six separate font files, each adding roughly 150–400 KB. Bundling all of them fights directly with the entry-level-device constraint in §9 and the 30 MB APK budget.

Two further consequences: Indic scripts have taller ascenders and descenders than Latin at the same point size, so the type ramp's line heights need validating per script; and translated strings typically run 15–30% longer. Neither is survivable by a fixed-height text container.

PRD §4.7 · §4.8

Notifications & profile

Profile is the app's identity and self-service surface — the one place an Influencer can answer "who does Humbee think I am, who am I linked to, and how do they reach me" without asking their Distributor.

Two rules shape every screen here. Every field declares whether the user can change it, and if not, who can — a locked field with no explanation produces a support call. And no role ever appears without its industry (§3.1), including in the roles list, where the manufacturers are surfaced underneath because a barbender recognises "Dalmia TMT" long before "Steel (TMT)".

Cross-cutting · PRD §5 · §9

The states that decide whether this app is trusted

Empty, offline, and error states carry more weight here than in most products. A new Influencer's first session is an empty app, and a work site's normal condition is no signal.

  • Amber, not red. Offline is normal at a work site, not a failure. Rule 09.
  • Timestamped cache, so the user knows exactly how stale the numbers are before acting on them.
  • Queued writes are visible and honest. A queued dispute must never look like it was delivered.

Before build

What these wireframes assume, and what they don't answer

Every item below changes a screen in this document. They are worth resolving before high-fidelity design begins, not after.

QuestionWhich screens it changesWhy it matters now
Dispute SLA3.4, support§4.3 creates a ticket but promises no response time. Without one, the dispute flow damages trust rather than building it.
Corrected allocations3.3, 6.2, notificationsWhen Ops corrects an allocation that already produced points and possibly a reward, the user sees their balance fall. That needs designed copy, not a silent ledger entry.
Leaderboard consent9.1Opt-in is required by §4.9 but the consent screen isn't drawn. Showing one Influencer's volume to peers is sensitive.
Numerals in HindiEvery screenDevanagari or Latin digits? Trade users generally read Latin for quantities — worth confirming with real users rather than assuming.
Which languages ship in Phase 10.0, 0.0b, 8.3§13 Q4 is open. Each added language is a translation budget, a font asset, and twelve notification templates — not a config flag. The chooser scales to any number; the programme does not.
Notification template coverage0.0, 8.3, all §7 triggers§4.0 commits to sending push/SMS/WhatsApp in the user's chosen language. Every §7 trigger needs a template per language, and the SMS gateway must handle Unicode — which costs more per message and cuts the segment from 160 characters to 70. At twelve triggers across seven languages that is 84 templates to author and maintain.
Script font strategyEvery screenLato is Latin-only. Six Indic scripts mean six font files at 150–400 KB each, against a 30 MB APK budget on 2 GB devices. Bundle, download on demand, or rely on system fonts? This decision belongs in the design system, not in a screen.
Cash reward KYC4.1, 4.2§13 Q1 is open. If cash payouts need KYC above a threshold, Rewards gains a blocking state that doesn't exist in these frames.
Unlinked partner history3.1, 3.2Does an Influencer still see allocations from a partner they've since unlinked? Not covered by the PRD; changes the filter model.
Points expiry rule6.1, 6.2§4.6 says "e.g. 12 months". An example is not a shippable rule, and the expiry warning copy depends on it.
Icons not yet in the system4.3, 6.1, 9.1, 11.1Lucky draw, points/coin, leaderboard, referral, trophy and industry marks don't exist in the HUMBEE library yet. They need drawing before high-fidelity.
The dependency outside this document

These screens are only as good as the data behind them. PRD §12 assumes the Distributor/Dealer app will be extended so partners can record allocations against an Influencer. If that work isn't scheduled, every screen here renders empty on launch — and the trust story the product is built on inverts. It is the single largest delivery risk in the programme and it sits on a different team's roadmap.
