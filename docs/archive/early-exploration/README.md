# Superseded exploration — `prototype/` and `wireframes/`

**Do not build from anything in these two folders.**

| Folder | What it is |
| --- | --- |
| `wireframes/influencer-app-wireframes.html` | Early low-fidelity wireframes (10 Aug 2026) |
| `prototype/influencer-app-prototype.html` | An early interactive prototype (11 Aug 2026) |
| `prototype/directions/01-ledger.html` … `04-celebrate.html` | Four competing visual directions explored before one was chosen |

All of it predates the design handoff and **none of it matches the approved design.** Opening these
files will actively mislead: they use a warm off-white page (`#faf8f5`), a system-ui font stack, and a
different type ramp — where the approved design is **white-first, Lato throughout**, on the token set in
`../../design_handoff_humbee_influencer_app/docs/02-design-tokens.md`. The screen inventory differs too.

**The design spec of record is `../../design_handoff_humbee_influencer_app/`:**

- Screen specs — `docs/04-screens/`
- Tokens — `docs/02-design-tokens.md` and `design/tokens/*.css`
- The live visual reference — `design/prototype-standalone.html`

They are kept because they record how the visual direction was arrived at, which is occasionally worth
knowing. That is their only remaining use.
